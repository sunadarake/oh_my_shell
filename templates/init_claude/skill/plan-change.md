# 仕様変更・追加

変更内容: $ARGUMENTS
加えて plans/inbox.md に書かれている項目もすべて対象にする。
どちらも空なら、その旨を伝えて終了する。

前提: 私は plans/plan.md を読みません。plan.md の読み書きはすべてあなたが行い、私には要点だけを見せてください。

## 1. 読む
- plans/plan.md
- plans/summary.md
- AGENTS.md と todo/（存在すれば）

## 2. 影響を調べる
変更ごとに次を確認する。
- plan.md のどのセクションが変わるか
- 既存の決定事項と矛盾しないか
- AGENTS.md に影響するか
- todo への影響（未着手／着手中／完了済みに分けて）

## 3. 判断が必要な点があれば
私の判断が必要な点があれば、ファイルを変更せずに plans/reviews/NNN-review.md（既存の最大番号 + 1）に質問を書き出して止まる。
形式は /plan-review と同じ（選択肢・おすすめ・回答欄）。
回答後に /plan-update を実行すれば反映される旨を伝える。

## 4. 差分を見せて OK を待つ
ファイルを変更する前に、会話に次を示す。plan.md の本文は貼らず、要点だけにする。
- 変更の要約（1〜3行）
- plan.md: 追加／変更／削除する内容を箇条書きで
- AGENTS.md: 変更があれば
- todo: 修正する番号・追加する番号・不要になる番号
- 矛盾・懸念: あれば

## 5. 反映する（OK が出たら）
- plans/plan.md を更新し、「変更履歴」に日付と要約を1行追記する。
- plans/summary.md を更新する。
- AGENTS.md を必要に応じて更新する。
- todo は次のルールで扱う。
  - 未着手: 直接修正・削除してよい。
  - 着手中: 変更せず、どうするか私に確認する。
  - 完了済み: 書き換えない。修正が必要なら、続きの番号で新しい todo を追加する。
- plans/inbox.md から反映した項目を削除する。

## 6. 報告
3行以内で、何が変わったかを伝える。
