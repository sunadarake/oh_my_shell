# 実装計画の確定

計画ファイル: plans/plan.md

## 1. 事前チェック
次のどれかに当てはまれば中止し、該当項目を一覧で示す。
- plans/plan.md の「未決事項・質問」が空でない。
- plans/reviews/ に「状態: 回答待ち」のレビューが残っている。
- plans/inbox.md に未反映の項目がある（/plan-change を案内する）。

AGENTS.md や todo/ が既に存在する場合は、上書きせず、どう扱うか（追記／置き換え／続き番号で追加）を私に確認する。

## 2. AGENTS.md を作成
実装する AI が毎回読む前提で、簡潔に書く。
- プロジェクト概要（2〜3行）
- 技術スタック・バージョン
- ディレクトリ構成
- コーディング規約・命名規則
- テスト・ビルド・実行コマンド
- 禁止事項・注意点
- 作業の進め方: 「todo/ の番号順に1ファイルずつ実装し、完了条件を満たしたらチェックを付けて止まる」
- 仕様の詳細は plans/plan.md を参照する旨

## 3. todo を作成
todo/001-todo.md, 002-todo.md, ... の形式で作る。

- 1ファイル = 1回のセッションで終わる粒度にする。
- 番号順に実装すれば動く順序にする。
- 各ファイルは次の形式で書く。

```
# NNN: タイトル
状態: 未着手

## 目的
## 依存
（先に終わっている必要がある todo の番号。なければ「なし」）
## 作業内容
- [ ] ...
## 完了条件
（テストが通る、画面で○○が確認できる、など検証できる形で）
## 参照
（plans/plan.md の関連セクション）
```

「状態:」は 未着手／着手中／完了 のいずれか。/plan-change が変更してよい todo を判断するために使う。

## 4. 仕上げ
- plans/summary.md の「進捗」を「完了 0 / 全 Y」に更新する。
- CLAUDE.md に `@AGENTS.md` の行がなければ、追加してよいか私に確認する。
- 作成したファイルの一覧と、todo の依存関係を簡単に示す。
