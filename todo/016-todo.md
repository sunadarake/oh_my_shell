# ggc.sh: 引数なし時のコミットメッセージに変更ファイル一覧を含める

## 概要
`unix/ggc.sh` を引数なしで実行したとき、コミットメッセージを「日時 + ファイル数」の見出しと、変更ファイル一覧にする。何が変わったかがコミット履歴から分かるようにするため。

## 調査結果
- `unix/ggc.sh`: 引数なしだと `msg="update $(date '+%Y-%m-%d %H:%M:%S')"` を作り、`git add . && git commit -m "$msg"` を実行する
- 引数ありの挙動（改行区切りで結合）は変更しない
- `-h/--help` の説明に「メッセージを省略すると "update 日時" になる」とあるので、更新が必要
- `windows/ggc.ps1` は今回の対象外
- 他にスクリプト内の参照は `README.md` のみ（説明の確認が必要）

## 実装計画
- [x] ステップ1: 引数なしの場合は先に `git add .` してから、`git diff --cached --name-status` で変更一覧を取得する。日本語が引用符でエスケープされないよう `git -c core.quotepath=false` を付ける（`unix/ggc.sh`）
- [x] ステップ2: 1行目を `Update: YYYY-MM-DD HH:MM:SS (N files)`、2行目を空行、3行目以降を `Create: <file>` / `Update: <file>` / `Delete: <file>` / `Rename: <旧> -> <新>` にして msg を組み立てる。変換は `awk` で行う（`unix/ggc.sh`）
- [x] ステップ3: 引数ありの場合は従来どおり `git add . && git commit` にする。コミット処理が二重にならないよう整理する（`unix/ggc.sh`）
- [x] ステップ4: ヘルプ文の「メッセージを省略すると〜」を新しい形式の説明に更新する（`unix/ggc.sh`）
- [x] ステップ5: `README.md` に ggc の挙動の記述があれば合わせて更新する

## テスト・確認方法
- [x] 一時ディレクトリで git リポジトリを作り、新規・更新・削除・リネームを混ぜて `ggc` を実行し、`git log -1` の形式を確認する
- [x] 1ファイルのとき `(1 files)` と表記されることを確認する
- [x] 空白入り・日本語のファイル名がそのまま表示されることを確認する
- [x] 引数ありの挙動が変わっていないことを確認する
- [x] 変更がないときに、従来どおりエラーなく終わる（commit が「nothing to commit」になる）ことを確認する
- [x] `ggc -h` の表示を確認する

## 決定事項
- 対象は `unix/ggc.sh` のみ（`windows/ggc.ps1` は変更しない）
- 1行目は `Update: 2026-10-24 12:34:56 (3 files)` の形式
- 一覧は `Create: a.sh` / `Update: b.sh` / `Delete: c.sh` の形式、リネームは `Rename: 旧 -> 新`
- 1行目と一覧の間は空行
- ファイル名の空白はそのまま出力する。日本語は文字化けさせず日本語で出力する（`git -c core.quotepath=false` を使う）
- 1ファイルのときも `(1 files)` のまま（単数形にしない）

## 懸念点・未決事項
- `windows/ggc.ps1` と挙動が異なることになる（今回は許容）
- 空白入りのファイル名を awk で分割するとき、タブ区切りで処理する（`--name-status` の出力はタブ区切り）
