# README 作成・編集

README.md を、簡潔でわかりやすい日本語で書く。

## 手順

1. プロジェクトを調べる
   - 既存の `README.md` があれば読む（あれば「編集」、なければ「新規作成」）
   - `package.json`、`pyproject.toml`、`requirements.txt`、`Makefile`、`Dockerfile`、`.env.example` などから、セットアップ手順と実行コマンドを確認する
   - エントリポイントや主要ファイルを見て、何をするプロジェクトかを把握する
2. 下の「構成」どおりに README.md を書く
3. 書いたコマンドが実在するか（スクリプト名・ファイル名など）を確認する

## 構成

この 3 つの見出しだけを使う。順番も固定。

```markdown
# プロジェクト名

## 目的
（3 行程度）

## セットアップ
（コードブロックのみ）

## 使い方
（簡潔に）
```

### 目的
- 3 行程度。何を・なぜ作ったかを書く。
- 機能の羅列や宣伝文句は書かない。

### セットアップ
- コードブロック（```bash など）だけで書く。説明文は書かない。
- 必要なら、コマンドの横にコメント（`# 〜`）を短く付けてよい。
- クローンから実行できる状態までを、上から順に実行すれば済む形にする。

### 使い方
- 最もよく使う実行方法を先に書く。
- コマンド例と、1 行程度の説明だけにする。
- オプションが多い場合も、主要なものだけに絞る。

## 書き方のルール

- 日本語で、短い文で書く。
- 確認できなかったことは推測で書かない。不明点は README に書かず、作業後にユーザーへ伝える。
- 絵文字、バッジ、目次は付けない（ユーザーから頼まれた場合を除く）。

## 既存 README を編集する場合

README の記述を 1 つずつ、今のコードと照らし合わせて確認する。

### 確認すること
- コマンド：`package.json` の scripts、`Makefile` などに実在するか
- ファイル・ディレクトリ名：今も存在するか
- 依存関係・バージョン：設定ファイルの内容と合っているか
- 環境変数・設定項目：コード内で今も使われているか（`grep` で確認）
- 機能の説明：該当するコードが今もあるか、動作が変わっていないか

### 直し方
- **名前や値が変わっただけ** → 今の内容に書き換える
- **機能やファイル自体がなくなった** → その記述を削除する
- **正しい記述** → そのまま残し、構成に合わせて並べ直す
- **確認できない記述**（外部サービスの情報など） → 残して、作業後にユーザーに伝える
- 構成外の節（ライセンス、貢献方法など）は、消す前にユーザーに確認する。

### 作業後の報告
何を変えたかを、短くまとめて伝える。

```
- 削除：〜（理由：〜が存在しない）
- 修正：`npm start` → `npm run dev`
- 要確認：〜（コードから確認できなかった）
```
