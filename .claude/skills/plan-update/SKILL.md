# 実装計画の更新

計画ファイル: plans/plan.md
レビューファイル: $ARGUMENTS（空なら plans/reviews/ の番号が最大のもの）

前提: 私は plans/plan.md を読みません。plan.md の読み書きはすべてあなたが行い、私には要点だけを見せてください。

## 1. 拾う
次から情報を集める。
- レビューファイルの「回答:」と「追加メモ」
- 直前の /plan-review 以降の会話全体
- plans/inbox.md に書かれている項目

集めた内容を次のように振り分ける。
- 回答で決まったこと → plan.md の「決定事項」
- 追加された仕様 → plan.md の該当セクション
- 結論が出なかったこと・新たな疑問 → plan.md の「未決事項・質問」
- 決まったことに対応する未決事項 → 削除

回答欄が空の質問は未決事項として残す。
検討中の案や、私が迷っているだけの発言は決定事項にしないこと。

## 2. 差分を見せて OK を待つ
ファイルを変更する前に、会話に次を示す。plan.md の本文は貼らず、要点だけにする。
- 追加: （セクション名）内容
- 変更: （セクション名）変更前 → 変更後
- 削除: （セクション名）内容
- 矛盾・懸念: あれば

## 3. 反映する（OK が出たら）
- plans/plan.md を更新し、「変更履歴」に日付・要約・元のレビュー番号を1行追記する。
- plans/summary.md を更新する（形式は下記）。
- レビューファイルの「状態:」を「反映済み（YYYY-MM-DD）」に変える。
- plans/inbox.md から反映した項目を削除する。

## 4. 報告
残っている未決事項だけを番号付きで一覧にする。
未決事項が0件なら「/plan-finalize に進めます」と伝える。

## plan.md が無い場合
次の構成で新規作成してから反映する。

```
# 目的
# 決定事項
# 未決事項・質問
# 実装方針
# 変更履歴
```

## summary.md の形式
私が読むための要約。40行以内に収める。

```
# 計画サマリー（最終更新: YYYY-MM-DD）

## 目的
（1〜2行）

## 主な決定事項
- ...

## 未決事項（N件）
- ...

## 進捗
（todo 作成前なら「計画中」。作成後は「完了 X / 全 Y」）

## 最近の変更
（直近3件まで）
```
