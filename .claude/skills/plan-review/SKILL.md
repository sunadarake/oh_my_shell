# 実装計画レビュー

対象ファイル: $ARGUMENTS（空なら plans/plan.md）

## ルール
- コードは書かない。
- 計画ファイルは変更しない。作成してよいのはレビューファイルだけ。
- AGENTS.md・既存コード・plans/ 内の他のファイルがあれば読み、計画との食い違いも確認する。
- plans/reviews/ に過去のレビューがあれば読み、回答済みの質問を繰り返さない。
- plans/summary.md が plan.md の内容とずれていれば、問題点として挙げる。
- plans/inbox.md に未反映の項目があれば、それも踏まえてレビューする。

## 出力先
plans/reviews/NNN-review.md（NNN は既存の最大番号 + 1。最初は 001）

## レビューファイルの形式
```
# レビュー NNN（YYYY-MM-DD）
状態: 回答待ち

## 計画の理解
（3行以内。私の意図とずれていないか確認するため）

## 問題点
- [高] ...
- [中] ...
- [低] ...

## 質問
### Q1. 質問文
- 選択肢: A ... / B ...
- おすすめ: A（理由1行）
- 回答:

### Q2. ...

## 代替案
（あれば、トレードオフ付きで簡潔に）

## 追加メモ
（私が仕様の追加や補足を書く欄。空のままにしておく）
```

質問は最大7問。1問ずつ短く答えられる形にする。
私は plan.md を読まないので、質問は plan.md を見なくても答えられるように、必要な前提を質問文に含める。

## 書き出した後
- 会話には、ファイル名と「問題点・質問の件数」だけを示す。
- 私はレビューファイルの「回答:」と「追加メモ」に書き込むか、会話で回答・質問します。
- /plan-update を実行するまで plans/plan.md は変更しないでください。
- 会話で仕様が追加されたら、既存の計画との矛盾や影響範囲を指摘してください。
